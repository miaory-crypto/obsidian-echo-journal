# Privacy and data flow

ECHO 面向私人笔记，因此“数据什么时候离开设备”必须清楚、可预期。项目不包含遥测、开发者服务器或自动上传；但当你主动配置外部 API 时，相关文本会发送到你填写的服务商。

## 默认行为

- 新安装默认使用本机 Ollama 做 embedding。
- AI 解释与连续对话默认关闭。
- 项目不附带或代发开发者 API key；embedding 和对话使用两个独立 key，不会自动复制、回退或复用。
- 外部 API Base URL 必须是 HTTPS；只有 `localhost`、`127.0.0.1` 或 `::1` 可显式使用 HTTP。
- 远端模型回复按纯文本显示，避免模型生成的 Markdown 图片触发额外网络请求。

## 数据流

| 功能 | 触发方式 | 发送的内容 | 目的地 |
|---|---|---|---|
| mock embedding | 重建索引或检索 | 无 | 不联网 |
| Ollama embedding | 重建索引或检索 | 笔记片段或当前查询 | 你配置的 Ollama 地址，默认本机 `127.0.0.1` |
| 外部 embedding | 重建索引或检索 | 指定文件夹内的片段正文、标题/日期上下文，或当前查询 | 你配置的 embedding API |
| AI 解释 | 主动点击解释 | 当前笔记/选区、候选旧片段、文件名与日期 | 你配置的引导 API |
| 连续对话 | 主动开始或发送消息 | 当前笔记/选区、最多五条候选片段、近期对话 | 你配置的引导 API |

使用外部 embedding 时，插件要求先设置“日记文件夹”，避免误把整个 Vault 发送到外部服务。仍请在重建索引前检查目录范围，并阅读所选 API 服务商的隐私与保留政策。

外部能力采用 BYOK（Bring Your Own Key）：你直接向服务商申请凭据，项目不提供中转服务器。服务商条款、隐私政策、数据保留方式和可能产生的费用仍然适用。

## 本地保存内容

数据均为明文，没有应用层加密：

- `.diary-review/index.json`：片段正文、来源路径、日期、向量和索引元数据。
- `.diary-review/conversations.json`：当前与已归档的完整对话，以及查询来源标识。
- `.obsidian/plugins/diary-review/data.json`：插件设置、API key、收藏片段全文和用户标注。

这些文件可能被 Vault 同步、系统备份或第三方备份工具复制。请根据自己的同步与磁盘加密设置判断风险。不要把它们提交到 Git、附在 issue 中或分享给他人。

## 删除数据

先关闭 Obsidian，再通过文件管理器操作：

- 删除 Vault 内的 `.diary-review` 文件夹，可清除索引和对话记录；下次使用需重建索引。
- 在插件设置中清空 key，或删除插件目录中的 `data.json`，可清除设置与收藏；删除 `data.json` 会恢复全部默认设置。
- 卸载插件本身不会保证外部 API 服务商删除已经接收的数据；这部分受服务商政策约束。

删除前如需保留数据，请先自行备份。原始 Markdown 笔记不会被上述操作删除。

## 公开问题与日志

报告问题时只使用合成文本。不要附上真实笔记、完整错误响应、`data.json`、索引、对话文件或含私人路径的截图。详见 [`SECURITY.md`](../SECURITY.md)。
